# DB 성능/병목 리뷰

점검 대상: $ARGUMENTS

## 현재 상태

- Git 상태: !`git status --porcelain`
- 스테이징된 변경사항: !`git diff --cached --stat`
- 스테이징되지 않은 변경사항: !`git diff --stat`
- 최근 커밋: !`git log --oneline -5`

## 점검 범위 결정

- `$ARGUMENTS`가 특정 파일/디렉토리 경로면 해당 범위만 점검
- `--all`이면 리포지토리 전체에서 DB 접근 코드(ORM 엔티티/리포지토리, 쿼리 빌더, raw SQL, 마이그레이션 등)를 찾아 점검
- 인자가 없으면 기본적으로 diff만 점검: staged 변경사항이 있으면 그것을, 없으면 unstaged를, 그것도 없으면 가장 최근 커밋(`git show HEAD`)을 대상으로 함

## 점검 체크리스트

아래 항목은 실제로 코드에서 해당 패턴의 근거(구체적 쿼리, 반복문, 트랜잭션 경계 등)를 찾았을 때만 리포트한다. 근거 없이 일반론으로 나열하지 않는다.

**제외 범위**: 여러 리소스/서비스에 걸친 쓰기 정합성은 `consistency_review`, 다운스트림 호출 자체의 재시도·타임아웃은 `comm_review`, 예외 처리·에러 매핑 방식은 `error_review`, 레이어 경계 위반은 `arch_review`, 페이지네이션의 계약(응답 형태) 안전성은 `api_review`, SQL injection 등 입력 검증 자체는 `validation_review`에서 다룬다. 이 커맨드에서는 위 항목이 발견되면 지적하지 않고 해당 커맨드로 안내만 한다.

### 조회(Read) 계열

1. **N+1 문제**: 컬렉션을 조회한 뒤 루프 안에서 각 요소의 연관 엔티티를 다시 조회하는 패턴 (ORM lazy loading을 반복문 안에서 접근). 로그/코드에 같은 형태 쿼리가 반복될 소지가 있는지.
2. **카티전 곱 폭증**: 하나의 쿼리에서 컬렉션 fetch join(`JOIN FETCH` 등)을 2개 이상 동시에 거는 패턴.
3. **인덱스 미스 / 풀스캔 가능성**: `WHERE`/`JOIN`/`ORDER BY` 대상 컬럼에 함수를 씌운 경우(`WHERE DATE(col)=...` 등), 또는 인덱스 없는 컬럼으로 대량 테이블을 조회하는 경우. 스키마/마이그레이션 파일과 대조해서 확인.
4. **오버페칭 / `SELECT *`**: 필요 이상의 컬럼 조회, 큰 컬럼(TEXT/BLOB/JSON) 무분별 포함, 페이지네이션 없는 전체 조회.
5. **OFFSET 페이지네이션**: 대용량 테이블에 `LIMIT n OFFSET m` 방식이 쓰이는 경우 — cursor(keyset) 방식 대체 가능 여부 확인.

### 쓰기·트랜잭션 계열

6. **FK 참조 순서**: 한 트랜잭션에서 여러 엔티티를 저장/삭제할 때 부모/자식 순서가 맞는지, 순환 참조가 있는지.
7. **데드락 위험**: 여러 행/테이블을 잠그는 순서가 트랜잭션마다 다른지 (특히 정렬 없는 배치 UPDATE).
8. **락 경합 / 긴 트랜잭션**: 트랜잭션 범위 안에 외부 API 호출, 파일 I/O, 대기성 로직이 포함돼 있는지.
9. **벌크 처리 누락**: 반복문 안에서 단건 INSERT/UPDATE 후 매번 flush/commit 하는 패턴.

### 인프라·통신 계열

10. **커넥션 풀 고갈 위험**: 풀 크기 설정값, 커넥션을 오래 붙잡는 코드 경로, 획득/유휴 타임아웃 설정 여부.
11. **채티(chatty) 통신**: 루프 안에서 개별 쿼리·API 호출을 반복하는 패턴 (`IN` 절이나 배치 엔드포인트로 대체 가능한지).

### 설계 관점 (DDD)

- 애그리거트 경계가 과도하게 커서(연관 엔티티를 여러 개 물고 있어서) 로딩 시 N+1/오버페칭을 유발하는 구조인지.
- 목록/조회성 유스케이스가 도메인 모델을 그대로 거치는지, 별도 프로젝션·읽기 전용 쿼리(CQRS 읽기 모델)로 분리돼 있는지.

## 출력 형식

```
[DB 리뷰 결과]

1. [패턴명] - file:line
   증거: <실제 코드/쿼리 스니펫 요약>
   문제: <왜 병목인지>
   제안: <구체적 수정 방향>

...

점검한 범위: <diff / 경로 / 전체>
발견된 이슈: N건
```

이슈가 없으면 "점검 범위 내 병목 패턴이 발견되지 않았습니다."라고 출력한다.
